# 30. Import sheet, firmware settings storage, library management and app settings

Status: accepted, 2026-10-11

## Context
MVP steps 8, 11 and 12 (spec §8.1, §8.8, §8.9, §12) put Import from Oryx, the Firmware Settings page, the Settings scene, New Layout and the sidebar's layout menu over the existing use cases. Building them showed four gaps: `EditSession.setSetting` wrote Navigator settings to the layout config (Oryx, the codec and the generator keep them in the Navigator's options) and deleted `flowTap: 100`, which is flow tap's value when switched on; `Library.rename` and `duplicate` bypassed an open document; a window could not tell an empty library from one not read yet; and nothing created a blank layout.

## Decision
- **Settings storage** lives in the domain (`KeyboardLayout.storedValue(of:)`, `store(_:for:)`, `changedSettings()`): Navigator settings (those with `navigatorKinds`) go to `navigator.options`, everything else to `settings`; values equal to the unset value are removed. A toggleable slider's unset value is off (nil), so `flowTap: 100` is kept, as Oryx keeps it. `setSetting` routes through it and ignores ids outside the catalog. The sidebar badge and the inspector's Changed list count `changedSettings()` over all 100 settings, so imported changes outside the MVP sections still show and Reset All covers them.
- **Firmware Settings page (MVP):** the core sections only (tapping, one-shot, debounce, the RGB timeout, Navigator for the attached kind), filtered by board, Navigator kind and `dependsOn`. Sliders commit once per drag or ⏎ and clamp to whole steps in range (the generator refuses values out of range). Search, Modified only and the coupling notes wait for v1 with the other nine sections. Debounce, tap code delay, one-shot tap toggle and several Navigator options are shown although the generator can't write them yet; changing one makes the build refuse with the setting's name rather than drop it (ADR 0020). The generator should learn them.
- **Library:** `rename` renames an open document through `EditSession.setTitle` (undoable, and its next autosave keeps the title), then renames the package; `duplicate` writes an open document's pending edit first; `create` adds a local layout with a first `.save` revision ("New layout") so it opens unedited; `hasLoaded` separates loading from the Welcome. Move to Trash… asks first and is offered for a layout open in this window or in none: this window closes its own document first (Build & Flash stopped, last edit written, undo steps dropped); another window's document can't be ended from here.
- **New Layout** is a one-layer QWERTY layout Sextant authors (`KeyboardLayout.blankQWERTY`). It takes ⌘N (spec §9.1) and New Window moves to ⌥⌘N. An empty window opens the newest layout itself (`LayoutWindow`), so New Layout and Open after importing ask for another window only when this one shows a layout, or bring forward the window that has it.
- **Import sheet:** a filled-in reference (device card, ⌘K, Import from Connected Keyboard) is fetched at once; a typed one waits for Fetch or ⏎, so partial ids aren't fetched while typing. The preview shows the layers and counts, not a board (a board needs an `EditSession`; the window behind already shows how boards look). Saving is not cancelled by closing the sheet.
- **Settings scene:** General, Build and Privacy. The build backend choice is the `buildBackend` user default; the composition root reads it for each new `BuildFlashSession` and passes `SextantScenes` a status closure that only inspects the toolchain folder (nothing downloads before the setup step and the user's consent). Settings nothing reads yet (keyboard-connect action, flash notification, Oryx's build, heatmap and retention) are stored with `@AppStorage` for the steps that read them. Open at login is left out: it needs ServiceManagement, which the UI layer may not import; it arrives with a port.

## Consequences
- Navigator settings set in Sextant now reach the firmware and round-trip to Oryx's shape; flow tap can be switched on at 100.
- A window holding a layout keeps its title through renames from any window; duplicates never miss the last second of edits.
- Some MVP settings can make a build refuse until the generator supports them.
- An open Build & Flash keeps the backend it was created with until its window reopens the layout.
