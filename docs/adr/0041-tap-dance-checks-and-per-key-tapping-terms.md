# 41. Tap dance checks and per-key tapping terms

Status: accepted, 2026-10-12. v1 plan slice 1.1. Builds the per-key tapping term that ADR 0027 left out. Amended 2026-10-14 by v1 slice 2.3 (the last section).

## Context
The generator builds tap dances (the e5Rrr and JRGQm goldens), but a dance slot whose action its C can't run failed only at build time: a macro, a color key, a firmware key, TG, TT, OSL, LM, DF or OSM, or a tap that isn't a key. Spec §7.5 wants these caught as live issues first. `Key.tappingTerm` round-trips through Oryx's JSON and the generator writes it, but nothing in Sextant edits it, and the generator drops it without a word while the `perKeyTappingTerm` setting is off. Oryx's "Prefer tap in tap-and-hold dances" (`dancesTapAction`) sits on the Tapping section, but Oryx's output is the same with it on or off: JRGQm stores it off and e5Rrr leaves it on, both have dances, and both goldens share one dance template (research 02 §12 item 5; ADR 0040 lists it among the settings that write nothing).

## Decision
- **The domain decides what can run in a dance:** `KeyAction.runsInTapDance` (a key, modifiers, or MO or TO with a layer) and `typesInTapDance` (a HID or locale code: the tap is also typed on three or more taps). `KeymapPlan.token` uses them. A HID code (`isHIDCode`) is a `KC_` code other than a `KC_` spelling of an Auto Shift or Space Cadet key (`KC_ASTG`, `KC_LSPO`) or one of ZSA's module keys (Mouse Jiggler, Double Click): `register_code16` skips the handlers those need, so they would build and do nothing. `QMKCodes.statements` still writes the C, and a test checks that the two agree for every catalog code and alias, plain, with a layer, a chord, a color or a macro, and for unknown codes. The domain finds locale codes by their catalog category and the generator by its `i18n.h` table; the test catches any drift.
- **Live issues:** `.notInTapDance` (an error) lands on each dance slot that can't run, and on the tap when it isn't a key; on the tap it reads "A tap dance's tap must be a key", since a layer key there runs but can't be typed. `.tappingTermIgnored` (a warning) lands on a key, with no slot, that has its own term while per-key terms are off. Oryx built every fixture, and none of the seven raises either.
- **Setting a term** (`KeyboardLayout.setTappingTerm`): the value is kept within 0…1000, a value equal to the global term is stored as nil (as Oryx does), and every key on any layer with the same four actions, however their codes are spelled (`KC_NUBS` is `KC_NONUS_BACKSLASH`), gets the same value. QMK looks terms up by keycode, so those keys share one term anyway; a label, LED color or action description doesn't change the keycode. Dance and dual-function tokens are unique per key, so copying to an identical one is harmless. The generator's `get_tapping_term` writes one `case` per keycode, comparing tokens by their canonical spelling, since C rejects a second `case` for the same value. The global term is the stored `tappingTerm` or 200, read the way the generator reads `TAPPING_TERM`.
- **`EditSession.setTappingTerm`** is one undo step, "Set Tapping Term". A custom term also turns `perKeyTappingTerm` on in that step, since the firmware ignores the term otherwise. Going back to Global leaves the setting on: other keys may still use it.
- **The inspector row** (spec §5.1 item 7) shows when the key has a hold, a double tap or a tap then hold, read from the slots rather than `kind` (a label or macro changes the kind, not the timing). It also shows for any key that already has its own term, so an imported one can be set back to Global.
  - A pop-up offers "Global (200 ms)" or Custom; ADR 0027 keeps segmented controls out of the 280 pt inspector.
  - Custom adds a field and a 10 ms stepper, plus the difference: "+20 ms from global". Each stepper click is one step. A typed value commits on Return, when focus leaves or when the row goes. On macOS 26 the field reports every keystroke, so the row keeps the typed value as a draft, with the key it was typed for. A button click leaves the field focused, so the key can change under a draft (Make Transparent, Disable, a slot's pop-up, a swap or an undo); the draft then commits only onto a key with the same actions and is otherwise dropped. The label field follows the same rule. After a commit the field shows what was stored, which the domain bounds.
  - Choosing Custom stores nothing until the value changes. A value equal to the global term is stored as Global, but the row stays on Custom ("Same as global"), so a held stepper isn't removed as it passes the global term. Only choosing Global, or selecting another key, shows Global.
  - The label and term fields share one focus in the key inspector, so moving between them can't leave ⌘⌫ and ⇧⌘⌫ pointed at the key.
- **`dancesTapAction` is hidden** from the Firmware Settings page and the palette, since Oryx's firmware is the same either way. The hide is its own list, apart from the MVP's core-section filter that slice 2.3 removes. An imported value is kept, and the generator still writes nothing for it.

## Consequences
- Changing the global term leaves per-key terms as absolute values, as in Oryx, so a term that now equals the global one stays stored until it is set again.
- An imported `dancesTapAction` still counts in the page's changed total, the sidebar badge and the inspector's Changed list, as other settings the MVP page leaves out do. Slice 2.3, which owns those, leaves it out.
- A dual-function key (a tap and a hold, no dance) whose action can't run is still refused only at build time. That is outside this slice's issue kinds.
- Dance timing and terms can only be felt after a flash, and each flash needs the user's OK.
- Design-QA scenes: new `inspector-dance-flagged` and `inspector-term-custom` scenes (light and dark); the `firmware-settings` scenes lose the dances row. The reference snapshots and the five goldens are unchanged.

## Amendment, 2026-10-14: `dancesTapAction` with every setting on the page (v1 slice 2.3)
The MVP's core-section filter is gone, and "Prefer tap in tap-and-hold dances" stays hidden: its hide list moved from the UI to the domain (`SettingsCatalog.offers(_:)`, with the other settings Sextant keeps but doesn't offer; ADR 0040's amendment). An imported value is still kept and still writes nothing, and it no longer counts in the page's changed total, the sidebar badge or the Changed list; Reset All leaves it. The inspector lists it under "Kept from Oryx" when it differs from its default, as JRGQm's does. This replaces the consequence above that it still counts.
